## 1. 已确认的方向

### 1.1 用户明确提出的要求

- 整体以 macOS 27 为视觉还原目标，重视窗口、菜单栏、Dock、图标、材质、间距与动效的真实感。
- 网页承载个人介绍、生活、音乐和交友；提供可探索的 Mac 使用体验。
- 所见的可点击元素应有对应交互，应用不能只是图标或截图。
- 支持多应用窗口；补全关闭、最小化、放大恢复，以及 Dock 悬浮上升、放大等行为。
- VS Code 保留打开播放音乐、歌词转代码、关闭停止播放的核心体验。
- 添加 QQ、Gmail、网易邮箱、GitHub、终端、电话、FaceTime、日历、计算器、Safari 等应用。
- QQ 首先出现用户提供的登录页面，头像使用现有 `assets/qq.jpg`。
- Safari 指向个人网站 `https://lozic7.com`。
- 添加真实共享的留言墙，由 Mac 的信息或 FaceTime 等应用承载。
- 已确认采用独立留言服务：访客填写昵称即可留言，站长可管理和回复。
- 桌面加入日历、天气等大组件。
- 桌面前端可直接托管到 GitHub Pages 或 Vercel；首版不考虑手机端适配。
- 图标使用真实品牌图形，可从本地已安装应用、官方素材或 Wikimedia Commons 获取；保留便于替换的本地资源结构。
- 本轮产出需求与交互 Markdown；页面开发、服务配置和上线是后续工作。

## 4. 桌面与窗口的统一交互

### 4.1 首次进入

- 直接看到完整桌面，不要求注册、输入系统密码或经过长时间开机动画。
- 菜单栏在顶部，Dock 在底部，日历和天气组件在桌面留白处。
- 显示一张可关闭的轻提示：“欢迎来我的 Mac，点开应用逛逛，也可以给我留句话。”
- 初始不自动播放音乐；由打开 VS Code 等明确操作触发。
- 首次不自动弹出 QQ、Messages 或多个窗口，给访客探索空间。
- 参考桌面尺寸以 1440×900 为主，同时检查 1280×720 与 1920×1080；小笔记本屏幕仍须可操作。

### 4.2 窗口状态

每个应用统一支持关闭、正常、最小化、放大四种状态，并独立管理前后层级。首版每个应用一个主窗口，应用内部可有标签页、写信弹窗和详情面板。

| 操作 | 结果 |
| --- | --- |
| 点击未打开的 Dock 图标 | 创建或恢复应用内容，播放一次启动动画 |
| 点击已经打开的图标 | 置顶并聚焦，保留内容；不重复启动音乐和网络轮询 |
| 拖动标题栏 | 移动窗口；交互控件、文本输入和滚动区域不会误触拖动 |
| 拖动边缘／角落 | 调整窗口大小，遵守该应用最小宽高 |
| 点击任意窗口 | 置顶，菜单栏同步当前应用 |
| 红色关闭 | 关闭窗口并执行应用清理；草稿按各应用规则保留 |
| 黄色最小化 | 收入 Dock；运行指示仍保留；内容状态不丢失 |
| 绿色放大 | 占据桌面可用区域，保留可操作的菜单栏和 Dock；再次点击恢复原位置和尺寸 |
| 绿色按钮的布局菜单 | 可选左半屏、右半屏、恢复；菜单项执行真实窗口布局 |
| 双击可拖动标题区 | 放大／恢复 |
| 显示桌面 | 暂时收起窗口，再次操作恢复原窗口与前后顺序 |
| 浏览器尺寸变化 | 将窗口修正回可用区域，不能把标题栏遗留在屏幕外 |

网页中的放大不等同于浏览器全屏；如果提供“全屏体验”入口，应单独触发浏览器全屏 API。不得拦截系统保留快捷键造成浏览器误关闭。

QQ 登录页按照截图使用独立窗口外观：右上角 × 负责关闭，顶部空白可拖动；进入主界面后使用 Mac QQ 风格的窗口控制。

### 4.3 Dock

- 根据鼠标距离连续放大当前与邻近图标，基线稳定，上升自然；移出后平滑恢复。
- 图标上方显示名称；打开应用有运行圆点；消息数量只来源于真实未读记录。
- 启动时短暂弹跳，完成后停止；音乐播放不意味着图标永久弹跳。
- 最小化和恢复有对应动画，不能只改变透明度。
- 右键菜单支持打开／显示、最小化、关闭、保留在 Dock 等已实现动作。
- 支持拖动排序，并在当前浏览器记住布局。
- 默认固定 Finder、Safari、QQ、信息、Gmail、网易邮箱、GitHub、终端、VS Code、日历、FaceTime、计算器、系统设置。电话、天气、通讯录、备忘录、照片可从应用列表／Spotlight 打开并固定。
- 屏幕较窄时压缩合理间距或提供应用入口，避免图标越出屏幕；这不构成移动端适配承诺。

### 4.4 菜单栏、桌面菜单与通知

| 入口 | 对应交互 |
| --- | --- |
| Apple 菜单 | 关于这台 Mac、系统设置、显示桌面、锁定体验、重新进入桌面 |
| 关于这台 Mac | 展示站点名称、主人名片、网站版本和资源说明；不伪造访客硬件信息 |
| 锁定体验 | 展示可点击恢复的站点锁屏；无需系统密码 |
| 重新进入桌面 | 重置本次窗口状态和停止音乐；不会删除公开留言或本地草稿 |
| 当前应用菜单 | 显示对应已实现的文件、编辑、视图、窗口、帮助操作 |
| 时间 | 使用访客设备时区；点击打开日历／通知中心 |
| Spotlight | 搜索应用、联系人、站内笔记和已索引内容；键盘可选择并打开 |
| 控制中心 | 调整站内音乐音量、深浅外观、减少动态效果；显示当前播放 |
| 网络状态 | 展示浏览器提供的在线提示及留言服务连接状态；不假装控制电脑 Wi-Fi |
| 电池 | 仅在浏览器提供真实可用数据时显示百分比；否则省略或显示无数值状态 |
| 桌面右键 | 更换壁纸、添加组件、排列图标、显示桌面 |
| 通知中心 | 站内新留言／回复、播放和设置反馈；点击能到对应内容 |

网络提示不能仅凭浏览器在线标志宣称服务可用；留言请求结果决定留言服务状态。通知是页面内通知，首版不主动申请操作系统推送权限。

### 4.5 所有控件的共同规则

- 可点击元素至少产生明确的内容、状态、导航或系统动作；不能用统一“敬请期待”弹窗代替所有功能。
- 保留参考界面中的次要能力时，提供合理的禁用说明或具体替代路径；视觉保真不能依赖一批无效按钮。
- 菜单支持点击外部／Esc 关闭；按钮、菜单、表单有键盘焦点和可读标签。
- 所有关键操作同时提供鼠标入口；快捷键仅在相应应用和输入焦点范围生效。
- 区分加载中、空内容、失败、已完成状态；失败时提供能执行的重试或返回操作。
- 减少动态效果设置对窗口、Dock、歌词动效都生效。

## 5. 各应用的详细交互

### 5.1 VS Code：音乐与代码歌词

保留现有 Dracula 风格和歌词生成代码的表现，并按真实 VS Code 的标题栏、活动栏、侧栏、标签、编辑区和状态栏逐步还原。

| 操作／位置 | 行为 |
| --- | --- |
| 从关闭状态打开 | 从头播放当前歌曲，同步初始化代码歌词；播放授权失败时显示可直接点击的播放按钮 |
| 最小化／切换到其他应用 | 继续播放；控制中心和正在播放组件同步 |
| 红色关闭／菜单退出 | 立即停止、复位进度，取消延迟播放与歌词动画，清理重复监听 |
| 关闭后重新打开 | 从头开始，清除上次生成的歌词行；不会叠加多个音频实例 |
| `main.py` | 查看随歌词生成的代码 |
| `music.mp3` | 显示播放、暂停、进度、音量；拖动进度后歌词同步到正确位置 |
| `lyrics.lrc` | 查看当前歌词文件，可定位对应时间 |
| `about.md` | 显示简短个人介绍和其他应用入口 |
| `playlist.json` | 展示可用歌单；首版只有现有曲目时如实显示一首 |
| 标签关闭、重新打开文件 | 正常切换编辑内容；关闭单个文件标签不等于退出应用 |
| 搜索 | 搜索当前文件或歌词 |
| 播放结束 | 停留在结束状态，可重播；不自动无限循环，除非开启循环 |

必须检查“打开后立即关闭”“连续点击图标”“最小化后恢复”等情况，避免被旧计时器重新播放。浏览器音频限制应有明确恢复入口，不能要求用户盲点空白处。

### 5.3 Messages 信息：公开留言墙

这是整个站点的主要社交功能。外观还原 Mac 信息应用，数据属于真实公开留言。

#### 页面结构

- 左侧顶部：搜索、新建信息；置顶“给 Lozic 留句话”。
- 左侧列表：一条根留言对应一个会话，展示昵称、头像、摘要、时间和本浏览器的未读状态。
- 右侧：会话标题、公开留言标识、按时间排列的留言和回复、底部输入栏。
- 所有访客都可阅读公开留言；站长回复带经过服务端确认的主人标识。
- 头像默认使用根据昵称生成的首字／本地预设样式；首版无需上传头像或提供邮箱。

#### 发言流程

1. 点击新建信息，填写昵称和内容；昵称不代表登录身份。
2. 可选一个心情表情，也可附上站内歌单中的歌曲卡片。
3. 输入框旁持续说明“这是一条公开留言，其他访客也能看到”。
4. 点击发送后显示发送中，防止重复提交。
5. 服务端确认保存且可公开后显示“已发布”；若服务端要求审核，显示“等待审核”。
6. 发送失败保留输入内容，提供重试；不能把仅存在本地的消息标为已发布。

默认昵称长度 1–24 个字符，文本长度 1–1000 个字符，空白内容不可提交。服务端也必须执行输入校验与发布限制。首版内容为文字、表情、受限站内歌曲引用，不开放图片、语音和视频上传。

#### 会话与身份

- 使用服务端留言 ID 作为会话主键；相同昵称不会合并为同一个人。
- 回复关联父留言／根留言 ID，展示为同一会话里的气泡。
- 主人身份来自经过认证的后台账号信息，不能凭昵称、头像或提交的邮箱判定。
- 左右气泡区分访客留言和主人回复；不靠气泡位置冒充访客已登录。
- 展示“已发布”“等待审核”“发送失败”，不虚构“已读”“对方正在输入”或实时在线状态。
- 游客可回复、复制、搜索留言；删除和审核属于后台管理员能力。若后续支持游客编辑，必须增加可验证的权限机制。
- 评论删除后在两种应用视图中同步消失或显示已删除状态，不保留可继续回复的失效会话。

#### 歌曲与心情

- 歌曲只能从站内已存在的曲目中选择，用稳定曲目 ID 映射本地资源；禁止执行留言里任意提供的资源 URL。
- 心情和曲目引用随同一条留言持久保存，约定可解析的内容格式并保留普通文字回退；不另建音频上传系统。
- 点击歌曲卡片，通过统一打开应用行为启动／切换 VS Code 播放。
- 服务端数据格式变更或引用曲目已删除时，回退为文字卡片，不导致整条留言无法阅读。

#### 同步与通知

- 打开 Messages／FaceTime 时请求最新数据，支持分页和显式刷新。
- 页面可见时可约每 30 秒轻量检查更新；切到后台或关闭相关应用时暂停不必要的请求。
- 这属于定期更新，不宣称即时聊天；首版不要求 WebSocket。
- 首次加载不把所有历史留言弹成新通知；只提示首次基线之后的新留言或回复，并按 ID 去重。
- 已读游标和草稿只保存在当前浏览器，不声称跨设备同步。
- 点通知或 Dock 未读标记能进入对应会话；没有新消息时不伪造红点。
- 服务不可达时展示连接状态和重试；服务未配置时显示配置说明／明确标识的演示内容，不混入真实留言。

2. **来访回信**：FaceTime 看到网站来访记录 → 发信息 → 定位公开会话 → 查看主人的真实回复。
3. **了解生活**：Finder 打开关于我 → 备忘录读到随笔 → Safari 访问个人网站 → Messages 留言。
4. **开发者彩蛋**：终端输入 `contact` 看名片，输入 `play` 听歌，输入 `open messages` 打开留言。
5. **日历回忆**：真实里程碑 → 当时的笔记或作品 → 相关歌曲；素材不足时只显示已有内容。

这些入口调用同一套应用打开和播放器状态，不为每个入口重复构建窗口或启动第二段音频。

## 7. 留言服务与部署

### 7.1 静态桌面与独立服务

```text
访客浏览器
  ├─ 静态桌面：GitHub Pages 或 Vercel
  │    ├─ HTML / CSS / JavaScript / 本地图标与音频
  │    └─ Messages 与 FaceTime 自定义界面
  └─ HTTPS 请求：独立 Waline 服务
       ├─ 公开留言读取、发布、回复、校验和发布限制
       ├─ 站长管理后台：认证、回复、审核、删除
       └─ 持久数据库：保存共享留言
```

GitHub Pages 负责静态文件托管，不直接执行留言写入逻辑；因此“桌面可直接静态部署”和“留言需要在线服务”同时成立。[GitHub Pages 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

Waline 提供第三方客户端可调用的接口，适合用自绘信息应用承载其数据；不直接把默认博客评论框嵌入 Mac 窗口。[Waline API](https://waline.js.org/reference/api/)

默认部署路径是独立 Vercel Waline 项目配持久 PostgreSQL 数据库；官方快速上手当前给出了 Vercel 与 Neon 的配置流程。上线时核对账户、地区、服务额度与实际配置，不承诺永久免费或自动完成开通。[Waline 部署说明](https://waline.js.org/guide/get-started/)

### 7.2 发布与管理规则

- 普通访客只需昵称和内容；前端不强制邮箱，服务端不配置强制登录。
- 服务端限制发布频率，校验长度，处理垃圾留言；有需要时启用验证码。只在前端限制按钮不能代替服务端保护。
- 默认普通留言校验后公开；保留后台审核开关，服务端返回待审核时前端准确呈现。
- 显示来源域名配置与跨域访问配置在实际部署后验证；允许本站两个托管环境，不能把公开域名配置当成身份认证。
- 留言按文本／受控格式渲染；过滤不可信 HTML、链接协议和内容引用，避免用户内容执行脚本。
- 站长从 Waline 管理后台回复、删除、审核；桌面展示主人回复。后台认证与公开留言身份分离。
- 管理账号、数据库口令、邮件凭据和服务端密钥只能存在服务端配置中，不能写入公开仓库或浏览器配置。
- 默认不展示访客 IP、地区或设备标签；服务端实际收集项在隐私说明中如实列出。
- 邮件通知不属于留言必需条件；以后配置后再启用，不影响昵称留言的主流程。

发布频率、审核、访问域名和隐私显示配置以实际版本为准，参考 [Waline 环境变量](https://waline.js.org/reference/server/env.html) 与 [安全说明](https://waline.js.org/guide/features/safety.html)。

### 7.3 数据边界

| 数据 | 保存位置 | 是否与其他访客共享 |
| --- | --- | --- |
| 公开留言、公开回复 | Waline 持久数据库 | 是 |
| 主人联系方式、公开介绍、曲目、相册清单 | 静态配置／资源文件 | 是，随站点发布 |
| QQ 演示会话、登录模拟状态 | 内存／本地偏好，按功能明确生命周期 | 否 |
| 留言草稿、昵称偏好、已读游标 | 当前浏览器本地存储 | 否 |
| 邮件草稿、本地笔记、提醒、收藏、桌面布局 | 当前浏览器本地存储 | 否 |
| 管理员凭据、数据库密钥 | 服务端环境与管理后台 | 不向访客公开 |

匿名昵称不是可靠身份。首版不提供匿名私信、游客跨设备身份同步或未经认证的删除功能；所有公开留言都能被其他访客看到。

### 7.4 配置与上线准备

实现阶段需准备：静态站点地址、独立留言服务地址、数据库连接、管理员账号和允许的访问域名。前端只配置公开服务地址及功能开关。

两个部署域名访问同一留言墙时，使用固定逻辑标识（例如 `personal-mac/guestbook`），避免因 GitHub Pages 子路径或 Vercel 域名不同而生成两套留言。开发／预览环境使用独立标识或测试服务，避免测试消息污染正式数据。

静态资源使用适配仓库子路径的相对路径；默认不依赖必须配置服务器重写的路由。后续部署文档分别写清 GitHub Pages 与 Vercel 的步骤。

## 8. 实现组织与性能原则

推荐结构用于拆分现有单文件，名称可按实际需要简化；不要为目录结构本身增加框架。

```text
index.html
assets/
  qq.jpg
  icons/
  wallpapers/
  photos/
  SOURCES.md                 # 实现时生成：资源来源、版本和替换说明
styles/
  desktop.css
  windows.css
  apps/
scripts/
  main.js
  config.js                  # 公开资料、应用清单、公开服务地址
  desktop.js                 # 窗口、菜单、Dock、通知与焦点
  player.js                  # 唯一音频状态和歌词同步
  guestbook.js               # Waline 数据访问及状态转换
  apps/                      # 各应用内容和事件
music.mp3                    # 保留现有文件
lyrics.lrc                   # 保留现有文件
docs/
  MACOS_DESKTOP_SPEC.md
  references/qq-login-reference.png
```

- 统一窗口生命周期、应用注册、打开应用入口和音乐状态，避免各应用各写一套窗口控制。
- 信息和 FaceTime 共享数据访问与缓存；QQ 演示消息使用独立状态。
- 简历、介绍、头像、联系方式、歌单和图库集中配置，便于主人自行更换。
- 使用浏览器可原生加载的模块；是否增加依赖以真实需要决定。
- 图标和壁纸本地化；图片有明确尺寸，加载失败有可识别回退。
- 长留言列表分页／按需渲染；切后台暂停不必要轮询。
- 动画优先使用位移与缩放；拖动时控制大面积模糊与重排开销。
- 给每个应用定义销毁动作，关闭后清理定时器、事件与过期异步响应。
- 公共数据接口失败不阻塞桌面、计算器、终端和音乐等本地功能。

## 9. 逐步实现顺序

| 阶段 | 工作 | 完成标志 |
| --- | --- | --- |
| 0. 视觉与资源 | 固定系统参考、QQ 截图、应用参考和图标；梳理公开配置 | 有可比对的参考与来源清单，不靠记忆混搭界面 |
| 1. 桌面基础 | 菜单、窗口、Dock、焦点、拖拽、尺寸、通知和设置 | 至少三个窗口同时操作稳定，所有窗口控制可用 |
| 2. 保留音乐与 QQ | 重构 VS Code 生命周期；实现 QQ 登录和会话联动 | 打开／最小化／关闭播放符合要求，QQ 截图和操作可逐项验收 |
| 3. 真实留言 | Messages、FaceTime 来访视图、Waline、管理后台 | 两个独立浏览器能看到同一留言和主人回复 |
| 4. 联系与浏览 | Safari、Gmail、网易邮箱、GitHub、电话、终端 | 联系入口可完成，外站受限和写信交接都有可用回退 |

分阶段不代表删减用户列出的应用；每阶段完成后继续逐个补齐。先搭窗口和共用行为，可以避免后面每个应用重复修同一问题。

### 10.1 视觉与桌面

- [ ] 系统界面、原生应用与选定参考图逐项对照：字体、图标尺寸、间距、圆角、边框、阴影、模糊和控件状态。

- [ ] 官方品牌图形来自核实资源，正式 Dock 不混入 Emoji 占位图标。
- [ ] 多窗口拖动、调整大小、焦点、关闭、最小化、放大恢复正常。
- [ ] 最小化再恢复保留窗口内容；浏览器缩放／尺寸变化后仍可找到窗口控制。
- [ ] Dock 相邻图标连续放大，提示、运行点、右键菜单和恢复行为一致。
- [ ] 首版约定的全部应用都能打开，并完成本节对应的主要任务。
- [ ] 每个可见可交互控件有动作；禁用项有明确原因，不能大量依赖通用提示糊弄。

### 10.2 音乐与跨应用

- [ ] 打开 VS Code 播放；最小化继续；关闭立即停止；再次打开从头。
- [ ] 快速打开关闭、重复点图标，不会延迟重播、双重音频或重复歌词。
- [ ] 音量、暂停、进度与控制中心／组件一致，歌词定位正确。
- [ ] QQ、终端、Messages 歌曲卡片都使用同一播放器与窗口。
- [ ] 音频被浏览器限制时有可点击恢复按钮。

### 10.3 真实留言

- [ ] 浏览器 A 留言成功，独立浏览器 B 能读取；刷新后仍存在。
- [ ] 无需登录或邮箱即可留言；必填和长度规则在服务端同样有效。
- [ ] 相同昵称不会自动合并或获得别人的权限；昵称伪装不能获得主人徽标。
- [ ] 主人真实回复展示在对应会话；删除或审核状态同时反映到 Messages 和 FaceTime。
- [ ] 发布失败保留草稿、可重试；不会误报成功；快速点击不会重复发布。
- [ ] HTML、脚本和恶意链接不能在气泡中执行。
- [ ] 服务未配置、断网、接口错误、发布限制、待审核都有明确界面。
- [ ] 首次加载不会把历史留言全部推送；通知按 ID 去重。
- [ ] 未经配置的摄像头／麦克风功能不弹权限请求，也不假装发生真实通话。

### 10.4 应用与部署

- [ ] QQ 复制正确账号，演示登录不提交真实凭据。
- [ ] Gmail／网易邮箱正确预填地址和内容，交接状态不冒充实际发送成功。
- [ ] Safari 打开个人网站；外部嵌入失败时仍能打开原站。
- [ ] 终端只执行站内命令，计算器有正确正常及错误结果，日历本地提醒不会公开上传。
- [ ] 天气数据明确来源、城市、时间；没有实时数据时不伪造。
- [ ] 两种托管环境下的静态资源、歌词、图标和留言接口路径正常。
- [ ] 仓库与构建产物没有服务端密钥；管理操作需后台身份。
- [ ] 用一次真实的跨浏览器留言／回复检查验证服务，不能仅靠本地存储演示验收。

实现验证优先覆盖窗口状态、播放器生命周期和真实留言等关键逻辑；视觉使用固定尺寸截图比对，简单文案与资源替换不额外堆砌测试。
