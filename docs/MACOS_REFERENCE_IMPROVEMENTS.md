# 个人 Mac 桌面：参考站对照与后续优化方向

日期：2026-10-19  
参考站：[macOS 27](https://macos27.kimi.page/)  
范围：产品体验、视觉细节、应用内容与改进优先级，不涉及具体实现方案。

实施进度：用户已确认按本文推进，当前已实现项目与尚待素材的部分见 [实现状态与交接](IMPLEMENTATION_STATUS.md)。下文保留初始对照与方向清单。

对照依据为本项目当前版本、用户反馈，以及参考站公开页面和前端资源。本次交互浏览器读取参考站超时，因此没有完成动画手感的直接体验；下文不把参考站的所有模拟能力视为真实系统能力。

## 1. 优先级结论

优先把窗口按钮与窗口动作打磨好，再调整桌面和 Dock 的组织方式，然后增加真正有用的小应用。

| 优先级 | 方向 | 希望得到的体验 |
| --- | --- | --- |
| P0 | 三色窗口按钮、关闭／放大／还原、最小化与恢复 | 每次操作都准确、自然，先消除目前最明显的生硬感 |
| P0 | 标题栏、工具栏、图标、菜单与焦点状态 | 不同应用打开后属于同一个系统，细节不打架 |
| P1 | 精简 Dock、丰富桌面、完善应用入口 | 常用应用容易找到，其他应用也值得探索 |
| P1 | 备忘录完善、独立待办、App Store 式应用中心 | 访客能留下内容、整理事情、发现小工具 |
| P1 | 地图基础功能与个人地点收藏 | 地图可以操作，也能承载主人的生活内容 |
| P2 | FaceTime 通话体验、更多应用联动 | 更有趣、更有参与感，同时保持功能边界清楚 |
| P2 | 时钟、倒计时、照片故事、便签等小工具 | 增加日常用途与再次访问的理由 |

## 2. 参考站值得借鉴的地方

参考站公开资源中，可以确认以下设计方向；这些是学习对象，不代表需要照搬其全部体量。[参考来源](https://macos27.kimi.page/)

| 参考方向 | 本站目前的差距 | 应借鉴的重点 |
| --- | --- | --- |
| 窗口按钮具有独立图形和状态，窗口动作有过渡安排 | 三色按钮图形、居中及状态表达不够准确，关闭、放大和恢复存在突变 | 细小控件的准确性与动作的连贯性 |
| 笔记有格式、标签、移动、恢复等整理功能 | 现有备忘录以阅读和基础文字编辑为主 | 让笔记成为可以持续使用的小工具 |
| 待办有列表、完成状态、日期、标记与优先级 | 本站只有日历提醒，缺少独立待办体验 | 用完整的小流程增强可用性 |
| App Store 有分类、详情、获取和打开流程 | 本站已有应用列表，缺少发现与选择应用的过程 | 把应用组织和探索本身做成体验 |
| 地图有在线底图、搜索、收藏和路线入口 | 本站没有地图应用 | 地点探索与个人生活内容的结合 |
| FaceTime 有呼叫、接听、挂断及本机摄像头预览 | 本站 FaceTime 主要展示留言来访 | 增加通话界面的参与感和控制反馈 |

需要区分：参考站的通话包含模拟连接流程，未验证真实双人音视频互联；地图中的部分导航行为也标明模拟。本站可以学习交互，不必为此建设完整通信或导航平台。

## 3. P0：先修好窗口的第一印象

### 3.1 三色按钮

- **最高优先级：修正圆形背景与内部图形的对齐。** 叉号、横线与放大图形都要在视觉上居中，不能贴边、偏上或偏下。
- 统一三个圆点的尺寸、间距、边缘质感，以及距离标题栏边缘的位置。
- 关闭、最小化、放大／全屏、还原分别使用语义准确的图形，取消目前不合适的箭头表现。
- 放大之后，绿色按钮应切换到对应的还原状态；不能一直显示同一个方向的箭头。
- 完善默认、悬停、按下、失焦四种状态，颜色与图形变化保持克制。
- 按钮看起来小巧，但实际点击要容易命中，不能要求访客精确点中一个极小位置。
- 按钮附近的点击不要误触拖动；拖动标题栏也不要误触关闭。
- QQ 登录页保留已确认的截图布局，其关闭按钮同样需要准确的图形、居中和反馈。

### 3.2 窗口动作

- 关闭时有短促、自然的离场反馈，避免窗口突然消失。
- 最小化应明确朝对应 Dock 位置收起，让访客知道窗口去了哪里。
- 从 Dock 恢复应有对应的回到桌面的过程，不能突然跳回原位。
- 放大和还原时，窗口边界、内容与标题栏协调变化，减少瞬间拉伸和跳动。
- 恢复后保留原来的位置、尺寸和正在查看的内容。
- 连续点击、快速切换状态时保持稳定，不出现半透明残留或窗口卡在途中。
- 打开新窗口时尽量保留上下文，让访客理解它来自哪个应用或入口。
- 动效采用统一节奏，以短、轻、自然为目标；复杂的“神灯”形变可以后置。
- **音乐规则保持不变：VS Code 打开播放、最小化继续、关闭立即停止，不能为了关闭动画延迟停歌。**

### 3.3 标题栏与多窗口

- 改善标题栏、应用工具栏和正文的衔接，减少重复的横条和过多的顶部留白。
- 对齐窗口标题、三色按钮和右侧工具，避免各应用出现不同的视觉基线。
- 前台窗口更清楚，后台窗口适度弱化；阴影、按钮颜色和标题状态一起表达焦点。
- 窗口拖动、边缘缩放和窗口吸附保持统一，边缘容易抓取。
- 放大、网页内全屏和浏览器全屏的入口与退出方式清楚区分。
- 绿色按钮可提供轻量布局选项，例如放大、居中、左右排列；不用一开始覆盖所有复杂窗口模式。

## 4. P0：补齐统一的系统细节

- 统一侧栏、列表行、输入框、分段按钮、弹窗的尺寸感与选中状态。
- 校准不同应用图标的可见大小、边距和清晰度，优先替换目前分辨率偏低的废纸篓图标。
- 让玻璃感主要服务于菜单、Dock 和浮层，正文区域保持稳定、易读。
- 统一菜单展开、菜单项悬停、点击外部收起、返回和取消的表现。
- 区分轻提示、局部状态和需要确认的弹窗，减少小操作被大弹窗打断。
- 已完成的操作要在列表、角标、按钮和相关应用中同步体现。
- “演示交互”“真实公开内容”“仅当前浏览器保存”的说明应清楚，但不占据整个应用的视觉中心。
- 保留减少动态效果选项，让动画是体验提升，而不是操作负担。

## 5. P1：让桌面、Dock 和应用中心各有分工

### 5.1 精简 Dock

- 默认保留约 6–8 个高频入口，优先考虑 Finder、Safari、QQ、信息、VS Code、备忘录和设置。
- 废纸篓保持在末端；其他应用可以按用户习惯固定或移出。
- 优化悬浮放大的连续性，减少图标抖动、互相挤压和提示标签跳动。
- 明确区分固定应用、正在运行的应用与最小化窗口。
- 应用名称、运行点和未读角标清楚且不过量；角标必须对应真实状态。
- 保留最近使用入口的可能性，但避免刚打开几个应用就把 Dock 塞满。

### 5.2 丰富桌面

- 在桌面放置备忘录、提醒事项、地图、App Store、照片等部分应用入口。
- 保留“关于我”“个人网站”等个人内容入口，让主人特色仍然突出。
- 支持桌面图标移动、对齐、排序和简单分组，减少固定写死的一排图标。
- 双击打开、单击选中、右键操作的规则保持一致。
- 适度增加文件夹，例如“联系我”“生活”“小工具”，避免桌面与 Dock 同时拥挤。
- 桌面大组件可以承担日历、待办和音乐状态，减少重复的应用图标。
- 默认继续使用 `original.jpg`，整体布局围绕这张壁纸安排留白。

### 5.3 应用入口分工

| 位置 | 适合放什么 |
| --- | --- |
| Dock | 少量高频应用和运行状态 |
| 桌面 | 主人希望访客发现的应用、文件夹和个人内容 |
| 所有应用／搜索 | 完整应用清单与快速启动 |
| App Store | 发现功能、了解用途、选择加入桌面的过程 |

## 6. P1：让备忘录更值得使用

- 在现有笔记功能上补充标题、基础文字格式、列表和勾选清单。
- 增加置顶、标签、文件夹整理和更明确的搜索结果。
- 优化笔记列表中的标题、摘要、更新时间与选中反馈。
- 清楚展示保存状态，让访客知道内容已经留下。
- 完善删除、恢复、导出与备份入口，形成完整的内容生命周期。
- 主人的公开笔记继续用于自我介绍、随笔、歌单和生活片段。
- 访客自己的笔记与主人的公开内容明确分开，保留私人使用感。
- 支持从笔记跳到歌曲、地点或待办，让内容能在应用之间流动。
- 首轮控制在常用编辑能力，不扩展成复杂文档协作平台。

## 7. P1：增加独立提醒事项／待办

- 提供新建、完成、取消完成、编辑和删除的完整操作。
- 增加“今天”“计划”“全部”“已完成”等直观视图。
- 支持几个可自定义的清单，例如生活、学习、想做的事。
- 支持简单的日期、备注、优先级和重要标记。
- 完成任务时有轻微但明确的反馈，已完成内容可以重新查看。
- 桌面待办组件显示当前任务和完成情况，点击即可继续处理。
- 与日历、备忘录互相进入，避免同一件事在不同应用中完全割裂。
- 主人的公开愿望清单和访客的个人待办分开呈现。
- 先提供当前浏览器内的可靠保存与页面开启期间的提醒；跨设备同步、复杂重复规则和后台持续推送后置。

## 8. P1：增加能使用的地图

### 8.1 基础地图体验

- 地图能够拖动、缩放，并可以回到选中的地点。
- 提供地点搜索、结果列表和地点详情卡片。
- 支持地点标记、收藏、最近查看和简单分类。
- 支持复制地点信息，以及在完整地图服务中继续查看。
- 地图、侧栏与地点卡片保持联动：选中结果后，访客能清楚看到对应位置。
- 在线内容加载失败时，保留已有收藏和可继续操作的入口。
- 如增加路线，先做简单的起终点与路线查看；实时导航、路况和复杂公交方案后置。

### 8.2 融入个人生活

- 增加“我喜欢的地方”“散步清单”“旅行回忆”等主人主动选择公开的地点集合。
- 地点可以附一小段文字、一张照片或一首关联歌曲。
- 点击地点故事，可以进入照片、备忘录或 VS Code 音乐。
- 让地图成为认识主人的另一种方式，而不是只有一个空的世界地图。
- 访客也可以保存自己的地点，明确这些收藏属于当前浏览器。

### 8.3 轻量范围

- 基础地图可以纳入 Pages 站点，在线底图和地点查询的依赖要清楚。
- 优先保证常用地点和搜索流程可靠，不追求复杂三维城市、离线地图或完整导航系统。
- 用户主动选择定位时再启用相关能力；默认可以通过搜索城市开始。

## 9. P1：增加 App Store 式应用中心

- 保留熟悉的发现页、分类、搜索、应用详情和打开入口。
- 分类可围绕“认识我”“生活”“音乐”“效率”“小工具”，贴合个人站点。
- 每个应用介绍清楚用途、可操作内容和适合从哪里开始。
- “获取”对应启用本站已有的小应用或加入桌面，随后可以直接打开。
- 允许管理已启用应用、从桌面移除、固定到 Dock，让桌面组织有明确入口。
- 用少量精选应用、主题或内容包丰富发现过程。
- 不加入真实支付、系统软件安装、庞大账号体系或开放插件市场。
- 评分、下载量和更新提示只在有真实依据时展示，不用虚构数字制造热闹。

## 10. P2：丰富 FaceTime 的通话体验

- 增加更完整的通话详情、呼叫、接听、挂断和返回流程。
- 可以提供用户主动开启的本机摄像头预览，以及对应的开关、画面布局和结束反馈。
- 通话界面的头像、联系人名称、控制栏和状态切换更加完整。
- 接入主人提供的欢迎视频或语音时，明确呈现为留言或介绍内容。
- 保留现有来访记录与公开留言联动，增加“继续发信息”“查看名片”等路径。
- 演示通话明确标识演示；真实通话可以通过已有会话链接或外部服务继续。
- 本阶段不建设自有多人音视频平台；避免为了一个展示入口引入复杂通信系统。
- 结束预览或关闭窗口后，设备使用状态应立即结束，界面反馈保持一致。

## 11. P2：其他值得补充的小应用与联动

| 方向 | 建议内容 | 范围控制 |
| --- | --- | --- |
| 时钟 | 本地时间、少量世界时钟、秒表、倒计时 | 先做好页面开启期间的使用体验 |
| 桌面便签 | 随手写一句话、调整位置、颜色和收起 | 保持轻便，不增加复杂编辑功能 |
| 照片故事 | 相册说明、照片备注、地点与音乐关联 | 优先补充主人提供的真实内容 |
| Finder | 更清晰的选中、预览、文件整理和最近项目 | 继续管理站内内容与访客自己的本地内容 |
| 应用概览 | 快速找到已打开窗口、切回当前任务 | 可先做简单清楚的窗口列表／概览 |
| 个人内容联动 | 笔记中的地点打开地图，待办进入日历，歌曲进入 VS Code | 复用已有应用，减少重复页面 |
| 通知中心 | 待办完成、留言回复、应用启用等状态聚合 | 避免重复通知与虚构未读数 |

可重点形成三条探索路径：

- 读一篇生活笔记 → 打开相关地点 → 看照片 → 听当时喜欢的歌。
- 在 App Store 发现小工具 → 加到桌面 → 新建自己的笔记或待办。
- 在 FaceTime 看来访 → 进入信息会话 → 查看名片 → 通过真实联系方式继续交流。

## 12. 始终保留的轻量边界

- **GitHub Pages 静态部署能力始终是基础要求。** 增加应用不应改变这一点。
- 浏览器内即可完成的小功能优先，不为每个应用增加独立在线服务。
- 保留已经决定的独立留言服务，其余基础桌面能力不应依赖它才能使用。
- 地图、天气和真实通话可能使用在线服务；服务不可用时，桌面和其他应用仍然正常。
- 不为了模仿一个控件或过渡效果引入整套大型依赖。
- 可选应用按需出现，媒体资源适量，避免为了增加数量明显拖慢首屏。
- 暂缓多人协作编辑、自建视频会议、复杂三维地图、真实软件安装与支付等方向。
- 保留本站已有特色：QQ 登录参考、个人头像与联系方式、Safari 个人网站、VS Code 音乐和原版壁纸。

## 13. 推荐推进顺序

1. 修正三色按钮的图形、居中和反馈，统一关闭、放大、最小化与恢复。
2. 校准标题栏和控件细节，调整 Dock、桌面与应用入口的分工。
3. 完善备忘录，增加提醒事项和 App Store 式应用中心。
4. 增加基础地图与个人地点内容。
5. 扩充 FaceTime 体验、时钟和便签，并打通应用之间的联系。

具体视觉与操作感受由用户试用后继续反馈，本轮不安排大规模体验测试，也不把以上方向直接视作已开始开发的功能。
